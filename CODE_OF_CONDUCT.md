# Code of conduct

## The short version

Be decent. Assume the other person is competent and acting in good faith, because they usually are.

## What that means in practice

Critique the code, not the person who wrote it. "This reissues on every run because the SAN list omits the common name" is useful. "This is amateur hour" is not, and it is also wrong, because that bug survived a full green test suite.

Say what you actually tested. Confident claims that turn out to be untested waste more of everyone's time than an honest "I think, but I have not checked".

Be patient with questions. Certificate handling is full of things that are obvious only once somebody has explained them, and the person asking has usually already read the documentation.

Not everyone here writes English as a first language, and not everyone has the same context. Ask what someone meant before deciding they meant something unpleasant.

## What is not acceptable

Harassment, personal attacks, sustained disruption, publishing anyone's private information, or any of the other things that make people stop contributing. This applies in issues, pull requests, commit messages and anywhere else connected to the project.

## Enforcement

Report a problem through [GitHub's private vulnerability reporting](https://github.com/albatrossflavour/puppet_certmanager/security/advisories/new), which is the only private channel this repository has, or by contacting the maintainer directly if you already know how.

Reports are read. The likely outcomes are a word with the person involved, deleting a comment, or blocking an account. This is a small project with one maintainer, so there is no committee and no appeals process, which is worth being honest about rather than pretending otherwise.
